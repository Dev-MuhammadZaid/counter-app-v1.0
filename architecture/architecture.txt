COUNTER APP — ARCHITECTURE

1. PROJECT OVERVIEW

---

Project Name:
Counter App

Project Type:
Small Vanilla JavaScript Application

Purpose:
A simple interactive counter that allows users to increase,
decrease, reset, and customize the counter step value.

The application also supports persistent data and light/dark
theme preferences using localStorage.

2. TECHNOLOGY STACK

---

HTML5
Provides semantic structure and user controls.

CSS3
Provides layout, styling, responsive behavior, themes,
states, and reusable design tokens.

JavaScript ES6
Provides counter logic, user interaction, theme switching,
and localStorage persistence.

Browser localStorage
Stores counter value, step value, and selected theme.

8. JAVASCRIPT ARCHITECTURE

---

JavaScript is divided into logical responsibilities.

A. DOM REFERENCES

Store references to:

- Counter display
- Increase button
- Decrease button
- Reset button
- Step input
- Theme button
- Body

B. STATE

Main application state:

count
step
theme

C. STORAGE

localStorage keys:

countNum
Stores current counter value.

locstp
Stores selected step value.

theme
Stores light/dark theme preference.

D. COUNTER LOGIC

Increase:

count + step

Decrease:

count - step

Reset:

count = 0

E. RENDER

renderCount()

Responsibilities:

- Update the counter display.
- Persist the current counter value.

10. FUNCTION RESPONSIBILITIES

---

getStep()

Returns a valid step value.

saveCount()

Stores the current counter value.

saveStep()

Stores the current step value.

renderCount()

Updates the visible counter and saves its value.

countUp()

Increases the counter using the selected step.

countDown()

Decreases the counter using the selected step.

resetCount()

Resets the counter to zero.

toggleTheme()

Switches between light and dark mode.

updateThemeButton()

Updates the theme button state and accessible label.

initialize()

Restores saved application state when the page loads.

12. VALIDATION

---

The step value must be:

- Numeric
- At least 1

Invalid values should not become the active step.

The counter should not become negative.

Preferred logic:

Math.max(0, count - step)

16. IIFE DECISION

---

An IIFE is not required for this project.

Reason:

The application is small and contains a limited number of
JavaScript variables and functions.

The main goal is readability and maintainability.

An IIFE may be useful when:

- Global namespace pollution is a concern.
- A project has many internal variables.
- A module-like private scope is intentionally required.

For this small application, normal ES6 code is sufficient.

17. REUSABLE CODE PRINCIPLE

---

Do not make every element generic.

Create reusable classes/functions when the same behavior
or visual pattern appears more than once.

For example:

.btn

can be useful when multiple buttons share the same base design.

Then specific variants can be added:

.btn-primary
.btn-secondary
.btn-danger

For this Counter App, avoid creating unnecessary abstractions.

18. MAINTAINABILITY RULES

---

1. HTML controls structure.

2. CSS controls appearance.

3. JavaScript controls behavior.

4. Theme colors should be controlled through CSS variables.

5. Avoid inline styles from JavaScript.

6. Avoid unnecessary functions.

7. Avoid duplicate CSS rules.

8. Use descriptive names.

9. Keep state management simple.

10. Validate user input.

11. Prevent negative counter values.

12. Keep localStorage responsibilities clear.

13. Do not introduce frameworks for a simple counter.
